# Dataset and Model Research Feasibility Decision — owner review

2026-10-30. **Proposed decision only; no ADR approved and no frozen source policy changed.** Evidence: [G2/G3 investigation](G2_G3_BLOCKER_RESOLUTION.md), [G4 investigation](G4_RCA_EVIDENCE_RESOLUTION.md), associated machine-readable source/candidate reports. Implementation checkpoint `d72e654`; branch from merged main `dd12339`.

1. **Can GAMMA support the current model targets?** Not from currently admitted evidence. Resource observations support source-specific numerical features. They do not establish live Checkout/Payment/Inventory HTTP RED semantics, certified healthy traffic, or verified gradual pre-SLO targets. RPC observations exist, but the audited tables have no HTTP status denominator and unverified units/mapping/completeness. Entire-archive absence is not claimed; full request traces are catalogued in four quarantined cases and are not silently admitted.
2. **Can G2/G3 be accepted without revising strategy?** No supported route is demonstrated. Current counts are 0 healthy train / 0 calibration per live service, versus 300/100. Additional approved original bytes could change feasibility only after actual semantic verification and valid independent outcome truth. Source renaming, row concatenation, intervention labels or merely more correlated windows cannot do so. Opening final holdout cannot cure the problem and is forbidden.
3. **What does Isolation Forest need?** At least 300 certified healthy training and 100 separate healthy calibration windows per modeled service, independent acquisition groups (current software floors 3/2), complete active traffic and objective SLO health, causal feature windows, native identity/unit provenance and compatible deployment features. Calibration/validation and heldout roles must be frozen before fitting. A source-backed certificate verifier must be implemented/reviewed; current self-attested report flags are now rejected. Numerical IF/MAD fitting and artifact roundtrip already work in fixtures.
4. **What does pre-SLO XGBoost need?** Independent gradual-run histories with separately observed SLO onset, valid strictly earlier predictors, verified negative/support intervals and both classes across allowed splits. Label availability must be separated from feature cutoff and source arrival. Intervention-active and post-incident samples cannot stand in for pre-SLO targets. No measured lead time or accepted artifact exists.
5. **Why 0.40 RCAEval coverage?** Only trace 0.25 and log 0.15 are supported. Model 0.25, SLO precedence 0.20 and deployment 0.15 are absent; receipt clocks are unknown. RE1 lacks even admitted trace/log support. Raw score cannot exceed supported weights, so both coverage and score floors are unreachable. Ground truth and injection clocks cannot be fed back into scoring.
6. **Which categories are recoverable?** Exact parent links, recorded span durations and fixed exception markers were already recovered. New work verifies acyclic ancestry, isolates native vs operational log methods and exposes source-byte/count/formula resolution. No additional weighted category was recovered. Unit/status/capacity uncertainty and arrival clocks cannot be repaired by guessing; numerical correlations are not causal proof.
7. **Can existing local scenarios qualify without threshold changes?** The actual seven captured incidents cannot: maximum business coverage 0.40, no approved model/change evidence, and shared symptoms retain ambiguity. Local onset support could raise theoretical coverage to 0.60 only when observed intervals are genuinely disjoint. Real independently observed deployment context might raise this further, but existing faults do not supply it. Coverage alone never guarantees score/margin/causality or remediation authorization.
8. **What improved and was verified?** Self-attested admission blocked before fitting, registry route/feature/window validation strengthened, research-method boundary repaired, trace cycles rejected, evidence references resolved, ablation exposure counted, source matrix/blockers emitted. 612 regression tests, schema/wheel checks, three actual RCAEval cases, seven raw incident replays and one current PostgreSQL/API incident check pass. Rankings/coverage are deliberately unchanged; this is safety and reproducibility improvement, not an accuracy gain.
9. **What needs research/design approval?** Any replacement/additional training source or change from live HTTP anomaly/pre-SLO prediction to offline resource anomaly requires the existing owner-reviewed ADR process. A new health/precursor evidence authority, any objective change and independent evaluation protocol must be specified before data selection/fitting. This report is review material, not permission to change accepted ADR-011 or score policy.
10. **What next within the remaining MVP schedule?** Preserve the working evidence-driven incident product with explicit model-unavailable and RCA abstention. Owner chooses one of the scoped routes below before a model training milestone is promised. Continue source-backed observability/admission work that is useful independently, not another incident infrastructure rewrite. Schedule estimates below are engineering planning estimates, not measured completion guarantees.
